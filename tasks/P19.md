# P19 — Resource nodes as ground gems, not black panels

**Builder:** Composer 2.5 · **Gap from:** `tasks/P18-critic.md` · **Shipped:** 2026-08-16

## Problem

P18 failed on a single gap: two oversized black ore-node panels (~15% viewport each) sat on top of the opening 8v8 clash. Resource entities used full `tile-ore`/`tile-gas`/`tile-sol` terrain sprites at unit scale, reading as 3-unit black squares with a gem inside. Silhouettes, HUD, and frame time already passed.

## Changes

### 1. Tight gem sprites (`src/atlas.ts`)

- Added `drawGem()` — 16×16 transparent sprites with only the glowing ore/gas/solar core (no dust fill, no magenta key).
- `putGem()` crops UVs to the tight 16×16 blit; atlas keys `gem-ore`, `gem-gas`, `gem-sol`.

### 2. Resource render scale (`src/render.ts`)

- `uvFor(Resource)` now points at `gem-*` keys instead of `tile-*`.
- Dedicated scale branch: `targetH = 0.85` world units (~0.7–1.0 range), ground lift `y = 0.38`.
- Smaller ground shadow for resources so blobs do not read as panels.
- Units and buildings unchanged.

### 3. Nodes ring the brawl, not cover it (`src/sim.ts`)

- `placeOpeningNode()` — single ground tile + gem entity for the opening tableau (no 7×7 ore panel).
- `stampOpeningGround()` rings ore/gas/solar at ±9 tiles from center (west/east/north/south).
- `stampPatch()` skips random spawns within 14 tiles of the opening look-at so procedural patches cannot bleed onto the clash pad.

### 4. Wing spacing (`src/sim.ts`)

- Fighter grid step increased `0.85→1.15` (cols), `0.95→1.25` (rows) so 8v8 wings stay readable instead of one merged blob.
